# Meta DAT — AI-Assisted MCP Setup

> _Original: [https://wearables.developer.meta.com/docs/develop/dat/ai-assisted-mcp/](https://wearables.developer.meta.com/docs/develop/dat/ai-assisted-mcp/)_

## Summary

Describes the **Wearables MCP server** at `https://mcp.developer.meta.com/wearables` —
an unauthenticated Streamable HTTP endpoint exposing two search tools:
`search_dat_docs` (Device Access Toolkit guides, API reference, code examples) and
`search_webapps_docs` (Display Web Apps docs). Both return up to 5 ranked doc sections,
raisable to 10 via `max_results`.

The page warns explicitly that the Wearables developer *site* URL is not an MCP endpoint,
and that stale `Authorization` headers cause spurious auth errors — the server needs no
token at all. That is the failure mode to check first when a client reports auth trouble.

Per-client setup is given for Muse Code, Claude Code, Codex, Cursor, and MCP Inspector.
Clients supporting plugins get the MCP server as a side effect of installing the DAT
plugin; Cursor and other file-reading clients add the endpoint manually as an HTTP MCP
server. For LocalGlasses the endpoint was registered directly in the project
[`.mcp.json`](/syntheses/localglasses-android-setup.md), which any MCP-capable client picks up.

## Key Takeaways

- Endpoint: `https://mcp.developer.meta.com/wearables` — Streamable HTTP, **no auth**.
- Tools: `search_dat_docs`, `search_webapps_docs`; `max_results` up to 10, default 5.
- Plugin installation (Claude Code, Codex, Muse Code) connects the MCP server automatically.
- Cursor-style clients add it manually as an HTTP server named `wearables`.
- MCP Inspector is the fastest direct check: Streamable HTTP → Direct → connect → initialize → List Tools → confirm `search_dat_docs`.
- Troubleshooting: wrong/old URL, unfinished initialization, stale auth header, or a query too vague to rank.
- Recommended habit: call `search_dat_docs` *before* choosing SDK APIs, and request Markdown output.
